# K1Blog 质量门禁、验证与交付规范

> 文档编号：06  
> 版本：v1.1.0  
> 上游：`00-项目执行宪法`、`01`–`05`  
> 适用范围：完成定义、CI 门禁、性能预算、安全门禁、发布回滚、事故处理、交付物

## 0. 目的

把「完成」从主观判断变成可复现的证据集合。任何人拿到同一份代码、同一组命令、同一组截图，都能得到相同结论。

当前工程已实现并通过本地门禁。本文中的命令、路径与实际执行结果以仓库和发布记录为准；未执行的门禁（例如目标机 Docker/Nginx）不得声称通过。

## 1. 完成定义（DoD）

一项工作只有同时满足以下条件，才可称为「完成」：

1. 目标与验收判据已写出，且实际达成。
2. 改动范围最小，没有夹带无关变更。
3. 适用的门禁全部通过，证据可复现。
4. 安全、性能、可维护、接手四视角已按相关性自审。
5. 未验证项、已知限制、风险、待决项已明确标注。
6. 相关文档已同步更新。
7. 没有用「应该」「大致」「后续再优化」掩盖未完成项。

## 3. 命令基线

以下命令已由 `package.json` 固化；实际名称以仓库为准：

```text
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm content:check
pnpm db:check
pnpm build
pnpm lighthouse
pnpm audit --prod
docker build
nginx -t
```

要求：

- 命令必须可在 CI 与本地重复执行；不得依赖本机绝对路径、个人配置、未提交文件。
- 构建/启动脚本只输出 ASCII，避免 Windows 终端编码异常。
- 命令失败时保留原始输出；不得只保留最后一行的「失败」。
- 未实际执行或无法执行的门禁，不得声称通过，必须标注为未验证。

## 4. 各门禁细则

### 4.1 G0 范围与契约

- 一句话目标 + 可判定验收判据。
- 改动面清单：文件、理由、受影响调用方。
- 风险清单：安全、数据、并发、缓存、兼容、性能、设计、可访问性；无则写「未识别到结构性风险」。
- 方案与取舍；有实质取舍时给出 2–3 个选项与推荐。
- 本轮明确不做什么。

### 4.2 G1 设计

UI 改动必须提供：

- 390 / 768 / 1440 / 1920 四档截图；
- 深色 / 浅色双主题；
- 正常动效 + `prefers-reduced-motion: reduce`；
- 悬浮、聚焦、激活、禁用、加载、错误、空状态；
- 无横向溢出、无文字裁切、无布局抖动；
- 对比度记录（正文 ≥ 7:1，辅助 ≥ 4.5:1）；
- 对照 `04` 第 1.3 节反模板红线逐项确认；
- 字体/图片/首屏 JS 预算。

缺少任一项，UI PR 阻断合并。非 UI 的小改动不得为了形式启动浏览器；但涉及响应式、交互、主题、无障碍的改动必须做可视验证。

### 4.3 G2 静态分析

- ESLint 9 flat config：Next 规则 + TypeScript + import 边界 + 无 `any` + 无 floating promise。
- Prettier 格式一致；CI 检查 `--check`。
- `tsc --noEmit` 通过；strict + `noUncheckedIndexedAccess`。
- 入口行数上限检查；`server-only` 边界；route handler 不得直连 `lib/db`。
- 禁止裸 hex、默认 UI 主题、禁用规则无说明。
- 禁止无用代码、注释掉的死代码、未使用变量（除非以 `_` 前缀明确保留并有理由）。

### 4.4 G3 单元/集成

- 单元：schema、工具、错误映射、加密、限流、内容解析。
- 集成：Route Handler、Server Action、评论 service、迁移、外键、幂等、审计。
- 每个用例独立临时 SQLite；测试结束清理；不得使用生产数据。
- 失败路径必须覆盖：空值、超长、非法格式、未认证、无权限、CSRF 失败、限流、重复提交、数据库失败。
- 覆盖率：核心领域分支 ≥ 90%，整体 ≥ 80%；不得用覆盖率伪造质量。

### 4.5 G4 端到端/无障碍

E2E 至少覆盖：

- 首页、文章页、标签页、归档页、搜索页、404。
- 评论提交 → 待审 → 管理员审核 → 公开可见；拒绝/删除不可见。
- 管理员登录、会话过期、CSRF 失败、越权。
- 主题切换、刷新保持、无 FOUC、减少动效。
- 移动端导航、触控目标、无横向溢出。

无障碍：

- axe 0 critical / 0 serious。
- 键盘走查：Tab 顺序、焦点可见、Dialog 焦点陷阱、ESC。
- 语义：标题层级、landmarks、表单标签、错误关联、图标按钮名称。
- 减少动效：内容完整、无空白、无裁切。

### 4.6 G5 性能

| 指标 | 目标 | 门禁 | 测量条件 |
| --- | --- | --- | --- |
| LCP | ≤ 2.5s | ≤ 2.8s | Lighthouse 移动配置，冷缓存 |
| INP | ≤ 100ms | ≤ 100ms | 交互路径实测 |
| CLS | ≤ 0.05 | ≤ 0.05 | 字体/图片加载稳定 |
| 首屏 JS | ≤ 160KB gzip | ≤ 180KB gzip | 首页/文章页 |
| 首屏字体 | ≤ 80KB | ≤ 220KB | 实际加载文件 |
| 字体资产总包 | ≤ 320KB | ≤ 320KB | 全部字体文件 |
| 单图 | ≤ 200KB | ≤ 200KB | AVIF/WebP |
| 单页总重量 | ≤ 1.2MB | ≤ 1.5MB | 冷缓存 |

- 每次 UI/依赖/字体/图片改动都必须复测；不得用旧报告。
- 性能回退超过 10% 必须解释；超过门禁必须修复或按第 16 节声明降级（性能不可作为安全/无障碍降级理由）。
- 禁止用移除内容、隐藏真实文本、降低可访问性来换取指标。

### 4.7 G6 安全

- `pnpm audit --prod`：无 high/critical；有则阻断。
- 密钥扫描：仓库、构建产物、日志、截图无密钥/令牌/真实邮箱。
- 依赖准入：新增依赖有理由、许可证、维护状态、体积、安全记录。
- 攻击面测试：评论 XSS/超长/空值/重复/限流/幂等；管理端 CSRF/越权/会话过期；SQL 注入（Drizzle 参数化）；开放重定向；路径遍历。
- 响应头：CSP、HSTS、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`、`frame-ancestors`。
- 错误响应不含堆栈、SQL、路径、密钥。
- 日志不含邮箱、IP、Cookie、Authorization；抽样核对。
- Nginx 限流、请求体限制、TLS 配置通过 `nginx -t` 与人工核对。
- 安全项不得降级；P0 安全缺陷阻断发布。

### 4.8 G7 内容

- frontmatter schema 通过；slug 唯一且与文件名一致。
- 草稿不进入生产；sitemap/RSS/搜索/OG 不含草稿。
- 断链检查通过；站外链接有安全属性。
- 图片有 alt、尺寸、图注；单图 ≤ 200KB。
- 代码块有语言、无真实密钥；示例数据非真实个人信息。
- 标题/摘要/标签/日期无占位文案；无 AI 填充内容。
- SEO title/description/canonical/OG/JSON-LD 正确。
- 内容质量清单逐项勾选（见 `05` 第 5 节）。

### 4.9 G8 数据

- 迁移在空库与既有库分别执行成功。
- 迁移前备份存在且可恢复；备份校验值记录。
- 外键、索引、CHECK 约束按 `02` 实现；查询有界。
- 评论状态机、审计、软删除、保留策略有测试。
- 破坏性迁移必须有明确审批、备份、回滚方案；否则阻断。
- 恢复演练记录可查；不得只在文档里声称。

### 4.10 G9 构建与打包

- `pnpm build` 成功；构建输出无秘密。
- standalone 输出完整；`public/`、字体、静态资源、迁移脚本、entrypoint 均被复制。
- Docker 多阶段构建成功；非 root；健康检查；镜像 Tag 与版本一致。
- `nginx -t` 通过；安全头、限流、缓存、请求体限制配置存在。
- 构建脚本 ASCII；版本号单一来源。
- 构建缓存不得掩盖失败；关键发布使用干净构建。

### 4.11 G10 部署与冒烟

发布前：

- 备份数据库；记录备份路径与校验值。
- 构建镜像并打不可变 Tag。
- 验证 Nginx 配置、健康检查、回滚镜像可用。

发布顺序：

1. 备份；
2. 停止旧实例或切换流量；
3. 执行迁移；
4. 启动新实例；
5. `live` / `ready` 健康检查；
6. Nginx 切换；
7. 冒烟：首页、文章、搜索、评论提交、管理登录、主题切换；
8. 观察错误率/P95/评论写入。

回滚：

- 切换上一镜像 Tag；
- 若迁移不可逆，恢复迁移前备份；
- 回滚后重新执行健康检查与冒烟；
- 记录原因、影响、恢复时间、后续动作。

### 4.12 G11 发布后观察

- 5xx 比例、P95、评论写入失败率、数据库大小、磁盘、备份状态。
- 发现异常先止损，再定位；不得边止损边重构。
- 事故记录：时间线、影响、根因、修复、预防；不虚构、不甩锅。

## 5. 安全与隐私门禁补充

- 评论不收集邮箱；IP 哈希、UA 截断，代码抽查 + 数据库抽查。
- 管理端会话、CSRF、审计三件套必须同时存在。
- 备份加密、限权、异机；恢复演练记录。
- 任何对外发送邮件/消息前确认收件人、内容、退订/隐私说明。
- 任何删除/导出/迁移按 `00` 第 4.4 节确认对象、范围、回滚、授权。

## 6. 证据与汇报

每个门禁证据格式：

```text
Gate: G5
Command: pnpm lighthouse
Result: LCP 2.51s / TBT 52ms / CLS 0.01 / JS 165KB
Artifact: CI 报告链接或本地路径
Confidence: 已验证
```

证据规则：

- 截图、报告、日志必须来自本次改动；不得用旧证据。
- 命令输出保留原始失败信息；不得润色。
- 无法验证时写明阻塞原因、影响范围、下一步；不得用「应该没问题」。
- 证据存 CI artifacts 或 PR 描述；大文件不入库；小报告可放 `docs/evidence/` 但必须可清理。
- 汇报按 `00` 第 10 节模板：结论、改动、验证、未覆盖/风险、待决。

## 8. 缺陷严重度

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 安全漏洞、数据丢失、构建失败、认证绕过、密钥泄露、生产不可用 | 立即阻断合并/发布，先止损 |
| P1 | 功能错误、关键路径失败、无障碍阻断、支持断点布局破裂、无界查询、缺少关键测试 | 合并前必须修复 |
| P2 | 非关键功能缺陷、可测的性能回退、维护性风险 | 可排期，但发布前评估风险 |
| P3 | 风格、文案、微调 | 不阻断；但违反 `04` 的视觉红线按 P1 处理 |

评审按严重度排序，给出定位与改法；不得只挑风格、不给优先级。

## 9. CI 流水线

建议阶段：

1. `install`：`pnpm install --frozen-lockfile`
2. `static`：lint、typecheck、format check、边界/行数检查
3. `content`：frontmatter、slug、断链、草稿排除
4. `unit`：Vitest 单元/集成
5. `build`：`pnpm build`、bundle 预算
6. `e2e`：Playwright 主路径
7. `visual`：四档截图、双主题、减少动效
8. `a11y`：axe + 键盘
9. `perf`：Lighthouse CI
10. `security`：audit、密钥扫描、headers/攻击面测试
11. `package`：Docker build、`nginx -t`
12. `release`：仅 main/tag 触发，需人工审批

分支保护：

- `main` 禁止直接推送；必须 PR + 通过门禁。
- 禁止绕过 CI；紧急修复也必须在合并后补齐门禁，不得长期豁免。
- 发布 Tag 必须与 `package.json` 版本一致。

## 10. 发布与事故

### 10.1 发布准入

- G0–G9 全部通过；G10 准备完成。
- 数据库备份可用；回滚镜像可用；Nginx 配置通过。
- 版本号、变更记录、发布说明已更新。
- 没有未决 P0/P1；P2 已评估。

### 10.2 发布后

- 观察至少一个稳定窗口；错误率、P95、评论写入、备份状态正常。
- 如果异常：先回滚/止损，再定位；不得在生产上试错。
- 发布记录：版本、时间、变更、验证、回滚点。

### 10.3 事故处理

1. 止损：回滚、关闭入口、隔离故障；不做未授权破坏性操作。
2. 保留证据：日志、请求 ID、时间线、影响范围。
3. 定位根因：可复现、可解释；说不清就标注为未确认。
4. 修复：最小改动；必须验证。
5. 复盘：原因、影响、修复、预防；不虚构、不追责式叙述。
6. 文档：更新 runbook、门禁或监控，避免复发。

## 12. 降级与例外

仅允许 `00` 第 7 节的三种情形：用户明示简化、临时验证任务、任务规模极小。

不可降级：

- 安全与隐私；
- 数据完整性与备份恢复；
- 无障碍；
- 评论输入校验与审核；
- 设计系统 token 与反模板红线；
- 关键路径测试。

降级声明必须包含条目、原因、影响与风险、恢复建议；未验证部分在汇报中标为未验证。
