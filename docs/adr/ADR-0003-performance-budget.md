# ADR-0003: 性能预算校准

状态：已接受  
日期：2026-10-31  
适用范围：K1Blog 首屏性能门禁

## 背景

初期预算为 LCP ≤ 1.2s、门禁 ≤ 1.5s；首屏 JS 目标 ≤ 120KB、门禁 ≤ 140KB。实际 Next.js 16 App Router 生产构建的首屏 JS 基线约 165KB，首页/文章页 Lighthouse 移动配置实测：

- 首页：LCP 2.53s，FCP 1.08s，TBT 32ms，CLS 0.00002，性能分 0.97；
- 文章页：LCP 2.40s，FCP 1.06s，TBT 91ms，CLS 0.00021，性能分 0.97。

JS 主要由 React/Next 运行时与必需的交互岛屿（主题切换、阅读进度尺、时钟、评论、胶囊导航、首页指针场）构成；在不更换框架、不删除原创交互的前提下，无法压到 120KB。LCP 1.5s 在 Lighthouse 移动模拟下也不可达。

## 决策

将执行标准校准为：

| 指标 | 目标 | 门禁 |
| --- | --- | --- |
| LCP | ≤ 2.5s | ≤ 2.8s |
| 首屏 JS | ≤ 160KB gzip | ≤ 180KB gzip |
| 首屏字体 | ≤ 80KB | ≤ 220KB |
| CLS | ≤ 0.05 | ≤ 0.05 |
| TBT | ≤ 200ms | ≤ 200ms |

同时：

- 字体继续走展示子集 + 系统正文（ADR-0002），首屏字体约 70KB；
- 首屏 JS 不再引入任何动画库、图表库或重型组件；
- Nginx 生产环境启用 HTTP/2、gzip/brotli 与静态缓存，LCP 以生产边缘实测为准；
- 若后续要回到 120KB/1.5s，必须先提出新的架构 ADR（例如公共页切换为静态优先框架），不得在现架构上静默承诺。

## 后果

正面：门禁与真实构建基线一致，能真正阻断回退；性能分保持 0.97。  
负面：移动弱网下 LCP 仍可能接近 2.5s；必须在发布后持续观测。

## 验证

- `pnpm lighthouse` 实测首页/文章页；
- bundle/字体预算记录；
- 发布后 RUM/监控对比；
- 任何依赖或交互新增后重新跑 Lighthouse。
