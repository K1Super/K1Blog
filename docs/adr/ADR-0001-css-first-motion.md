# ADR-0001: CSS-first 动效实现

状态：已接受  
日期：2026-10-31  
适用范围：K1Blog 首页、文章页、评论、管理端

## 背景

初期选型把 Motion 与 GSAP 列为候选，用于组件级动效与长滚动编排。视觉样张验证后，主视觉的动效来自：

- 首页引子、导语与 CTA 的 400ms 阶梯揭示；
- 阅读进度尺的滚动进度；
- 主题切换的 View Transitions 擦除；
- 右侧胶囊导航的药丸滑动（固定曲线，非弹簧库）；
- 首页 Canvas 指针场的距离衰减与坐标读数；
- 索引行、导航、CTA 的 120–240ms 状态迁移。

这些动效都可以用 CSS `@keyframes`、CSS 变量、`transform`、`opacity`、`clip-path` 与少量 `requestAnimationFrame` 实现，不需要动画库的运行时。

## 决策

MVP 不引入 Motion 或 GSAP。动效统一由 CSS token + 原生 JS 实现：

- 时长与曲线集中在 `styles/tokens.css` / 设计系统 token；
- 交互惯性只使用受控 `rAF`，不引入弹簧库；
- 组件库默认动画一律不使用；
- 如后续出现复杂的滚动编排、时间线控制或跨组件编排，再通过新的 ADR 评估 Motion/GSAP。

## 备选方案

1. 引入 Motion：组件级 API 方便，但会给首屏增加客户端 JS，且本项目的动效以 CSS 可表达的状态迁移为主。
2. 引入 GSAP：时间线能力强，但当前没有多段滚动叙事需求，依赖体积与许可证评估收益不足。
3. 纯 CSS + 原生 JS（当前）：体积最小、设计控制最强、减少动效路径最直接。

## 后果

正面：

- 首屏不加载动画库，保持 JS 预算；
- 动效 token 与设计系统强绑定，避免库默认弹簧与模板感；
- 主题切换、滚动进度、首页指针场与胶囊导航等交互更容易做到精准控制。

负面：

- 复杂时间线编排需要自己组织，未来可能需要引入轻量动画库；
- 需要自己维护 `prefers-reduced-motion` 路径与 `rAF` 清理。

## 验证方式

- 首屏 JS 预算检查；
- 390 / 768 / 1440 / 1920 视觉回归；
- `prefers-reduced-motion: reduce` 下内容完整；
- 阅读进度尺、主题切换、列表悬停交互实测。
