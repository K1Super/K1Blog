# K1Blog 内容、评论与数据规范

> 文档编号：05  
> 版本：v1.1.1  
> 上游：`00-项目执行宪法`、`02-企业级研发规范`、`04-视觉与交互设计系统规范`  
> 适用范围：MDX 内容、SEO、搜索、评论系统、自动审核、隐私、数据生命周期、备份恢复

## 0. 目的

把「内容即代码、评论即数据」两条链路固定下来：

- 内容来自 Git 中的 MDX，构建期校验、静态生成；
- 评论来自原生子系统，SQLite + Drizzle，完全自建 UI；
- 个人信息最小化、加密、脱敏；
- 所有数据操作有 schema、有审计、有备份、有恢复路径。

## 1. 内容模型

### 1.1 文件位置与命名

```text
content/posts/
  2026-10-24-precision-as-aesthetic.mdx
  2026-10-18-text-still-glows.mdx
```

规则：

- 文件名：`YYYY-MM-DD-{slug}.mdx`；日期为发布日期，slug 为稳定英文标识。
- `slug` 只允许小写 ASCII 字母、数字、连字符；长度 1–80；全站唯一。
- frontmatter 中的 `slug` 必须与文件名中的 slug 一致。
- 修改已发布文章的 slug 视为 URL 变更，必须提供重定向；不得静默改名。
- 文章资产放在 `public/content/{slug}/` 或受控内容目录；禁止外链任意图床。

### 1.2 Frontmatter Schema

所有字段由 `features/content/schema.ts` 的 Zod schema 校验；构建失败即阻断发布。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | 1–80 字符；不得为空模板文案 |
| `slug` | string | 是 | 小写 ASCII + 连字符；1–80；唯一 |
| `description` | string | 是 | 1–160 字符；用于 SEO 与索引 |
| `publishedAt` | ISO date | 是 | `YYYY-MM-DD`；不得晚于构建日期（预定发布除外） |
| `updatedAt` | ISO date | 否 | 有实质更新时填写；不得与发布时间矛盾 |
| `status` | `draft` / `published` | 是 | 生产构建只包含 `published` |
| `tags` | string[] | 是 | 1–5 个；每个 1–24 字符；标签名视为稳定 URL 片段 |
| `cover` | object | 否 | `src`、`alt`、`width`、`height`、`caption`；alt 必填 |
| `featured` | boolean | 否 | 是否进入首页推荐；默认 false |
| `canonical` | URL | 否 | 仅用于跨站转载；默认自 canonical |
| `ogImage` | string | 否 | 未提供时使用动态 OG |
| `locale` | `zh-CN` | 否 | 当前只支持中文；保留字段 |

禁止字段：

- 手写阅读时长（由字数计算）；
- 手写更新时间等于发布时间且无实质变更；
- 未定义的任意扩展字段；
- 与文章无关的营销标签。

### 1.3 草稿与发布

- `status: draft` 只在本地开发可见；生产构建排除。
- 预览不通过公开链接；如未来需要，使用签名预览令牌与过期时间，且不进入 sitemap/RSS/搜索索引。
- 发布前必须完成：schema、链接、图片、代码、SEO、可访问性、内容质量检查。
- 发布后修改正文必须更新 `updatedAt`；重大修订需在文末注明修订范围。
- 删除文章必须保留重定向或 410 策略；不得直接让 URL 404 无说明。

### 1.4 标签与归档

- 标签是文章元数据的一部分，不单独建表。
- 标签页 URL 使用稳定标签名（URL 编码）；标签改名视为 URL 变更，必须提供重定向。
- 归档按年月分组；归档页从内容索引生成，不手写。
- 标签数量控制在 1–5；禁止无意义标签堆砌。

## 2. MDX 安全与组件白名单

### 2.1 信任边界

- MDX 只允许仓库内受控作者编写；作者变更经过 Git 评审。
- 用户评论永远不进入 MDX/HTML 执行路径。
- 禁止远程 import、动态执行、`eval`、任意脚本、任意 `<script>`、任意 iframe。
- 禁止 `dangerouslySetInnerHTML`。
- 原始 HTML 只允许受控组件产生的结构；不得直接接受作者手写脚本。

### 2.2 组件白名单

允许使用：

- `Figure`：图片 + 图注 + 帧号；
- `Callout`：注释块，不使用通用彩色卡片；
- `Quote`：双线引用 + 编号；
- `ArchiveTable`：技术表格；
- `Footnote`：脚注；
- `CodeBlock`：由构建期 Shiki 渲染，禁止客户端高亮器；
- `Link`：站内/站外链接，站外自动 `rel="noopener noreferrer"`；
- `Divider`：发丝分隔；
- 受控的交互组件只能作为独立岛屿，按需加载，减少动效可降级。

禁止：

- 任意第三方 React 组件；
- 直接 HTML 表单；
- 外部脚本、追踪像素、广告；
- 未审查的 iframe、视频嵌入；
- 自动播放音频/视频。

### 2.3 代码块

- 构建期用 Shiki 着色；客户端只保留复制按钮。
- 语法主题限制在琥珀/骨白/氧化蓝三系；禁止霓虹主题。
- 代码块必须有语言标记；长代码可折叠，但折叠不得隐藏关键逻辑。
- 代码中的密钥、令牌、真实邮箱必须脱敏；示例使用明显占位值（非真实数据）。

### 2.4 图片

- 本地文件优先；如需远程图，必须白名单、缓存、尺寸限制。
- 必须提供 `alt`、宽高、图注；装饰图 `alt=""` 且不入正文语义。
- 图片处理为双色/低饱和、静态颗粒；禁止 AI 插画与通用图库拼贴。
- 单图 ≤ 200KB；使用 AVIF/WebP；响应式尺寸。
- 图注使用等宽 9px，包含帧号/来源；不得用图注承载正文关键信息。

## 3. 内容管线

### 3.1 构建期

1. 读取 `content/posts/**/*.mdx`。
2. Zod 校验 frontmatter；重复 slug、缺失字段、非法标签直接失败。
3. 解析 MDX，应用组件白名单；编译失败即失败。
4. 计算阅读时长（按中文/英文混排规则）。
5. 生成文章、标签、归档、首页数据。
6. 生成搜索索引、RSS、sitemap、OG 资源。
7. 运行内容质量检查（断链、图片、草稿、占位文案）。

### 3.2 搜索

- 使用 Orama + Mandarin tokenizer，构建期索引 + 客户端检索；中文分词必须可用。
- 索引只包含 `published` 文章；不得泄露草稿。
- 索引大小有预算；超出时拆分或压缩，不把全文塞进首屏 JS。
- 搜索结果展示标题、摘要、日期、标签；不展示正文全文。
- 搜索为空时显示简洁空状态，不使用插画。

### 3.3 RSS 与 sitemap

- RSS 只包含已发布文章；GUID 稳定；摘要 + 链接。
- sitemap 覆盖文章、标签、归档、静态页面；不含草稿、预览、管理端。
- 更新时间使用 `updatedAt` 或 `publishedAt`；不得伪造。
- 草稿、404、搜索页不得进入 sitemap。

### 3.4 OG 图

- 1200×630；使用深色/浅色 token、编号、标题、站点字标。
- 字体使用本地子集；不请求第三方渲染服务。
- 每篇文章有稳定 OG；缓存按内容版本失效。
- OG 图不得包含未公开信息、邮箱、IP。

## 4. SEO 与结构化数据

- 每篇文章：唯一 title、description、canonical、OG、Twitter Card（可选）。
- JSON-LD：`Article`（标题、日期、作者、图片）、`BreadcrumbList`；站点：`WebSite`、`Person`。
- 作者信息只展示公开笔名/简介；不展示私人邮箱。
- 标签页/归档页有独立 title/description；避免与首页重复。
- 分页/标签页 canonical 指向自身；不得全部指向首页。
- 站外链接 `rel="noopener noreferrer"`；赞助/联盟链接需明示。
- 禁止关键词堆砌、隐藏文本、虚假作者、虚假日期。

## 5. 内容质量门禁

发布前必须全部通过：

- [ ] frontmatter schema 通过，slug 唯一且与文件名一致。
- [ ] 标题、摘要、标签、日期无占位文案。
- [ ] 正文无 lorem ipsum、无 AI 填充段落、无「待补充」。
- [ ] 所有图片有 alt、尺寸、图注；无死链。
- [ ] 代码块有语言、可读、无真实密钥。
- [ ] 内外链可访问；站外链接有安全属性。
- [ ] 无草稿进入生产；无重复 slug；无断链。
- [ ] SEO title/description 长度合理；canonical/OG 正确。
- [ ] 可访问性：标题层级、链接文本、图片说明。
- [ ] 阅读时长、更新时间、标签与正文一致。

## 6. 评论系统架构

### 6.1 定位

- 原生评论子系统，不使用 Waline/Artalk/Giscus/Twikoo 等第三方挂件。
- 原因：UI 必须完全可控；评论是设计系统的一部分；数据与审核必须自有。
- 评论 UI 规范见 `04`；API/错误码见 `02`；数据模型见 `02` 与本文。

### 6.2 状态机

```text
提交 ──自动审核──┬─ 低风险 ──> approved（即时公开）
                  ├─ 边界风险 ─> pending ──人工/策略复核──> approved
                  │                              ├─reject──> rejected
                  │                              └─spam────> spam
                  └─ 高风险 ──> rejected / spam
approved ──delete──> deleted(soft)
rejected / spam ──purge──> hard deleted
```

- 新评论先经自动审核策略判定：低风险直接 `approved`，边界风险进入 `pending`，高风险按策略拦截为 `rejected` 或 `spam`。
- 自动审核关闭时，除蜜罐命中外一律进入 `pending`，不静默公开。
- 只有 `approved` 且未删除的评论对读者可见。
- `approved` 可软删除；软删除后读者不可见，管理端可审计。
- 有回复的父评论软删除后保留墓碑，不自动硬删除；无回复的软删除评论 30 天后硬删除。
- `rejected` / `spam` 保留 30 天后硬删除；`pending` 30 天未处理清理。
- 自动与人工状态流转必须在一个事务内完成，并写 `moderation_audit`；自动判定同时写 `comment_moderation`。
- 并发审核使用条件更新；状态已被他人改变时返回 `409 K1-ADM-001`。

### 6.3 层级

- 最多两级：顶层评论 + 一级回复；禁止无限楼中楼。
- 回复必须指向同一文章的已通过顶层评论。
- 父评论被删除/拒绝后，回复不展示；管理端保留审计。
- 评论排序：顶层按 `created_at ASC, id ASC`；回复按时间正序。

### 6.4 字段与限制

| 字段 | 约束 |
| --- | --- |
| `authorName` | 1–40 字符；去除首尾空白；禁止控制字符 |
| `content` | 1–2000 字符；纯文本；禁止 HTML |
| `parentId` | 可选；必须是同文章已通过顶层评论 |
| `website` | 蜜罐字段；必须为空；对用户不可见 |
| `formStartedAt` | 客户端提交时间；默认最小间隔 2 秒，由自动审核策略配置；对用户不可见 |
| `turnstileToken` | 可选；按部署配置启用 |
| `Idempotency-Key` | 16–64；必填；24 小时有效 |

- 内容中的连续空白压缩；前后空白去除；不接受纯空白。
- 链接不自动可点击；如需链接，白名单 + `nofollow ugc noopener`。
- 禁止在评论中存储 HTML、Markdown 渲染结果、图片、附件。
- 只收集昵称与正文，不收集邮箱或其他身份信息。

### 6.5 自动审核策略

自动审核是确定性的规则引擎，不依赖外部模型、网络服务或运行时密钥。策略以完整快照追加写入 `moderation_policy_revision`，每次保存生成新修订号，历史修订不可覆盖。

参数范围：

| 参数 | 约束 | 作用 |
| --- | --- | --- |
| 启用状态 | boolean | 关闭后除蜜罐外全部进入待审 |
| 自动发布上限 | 0–99 | 风险分小于等于该值直接发布 |
| 自动拦截下限 | 1–100，且大于发布上限 | 风险分大于等于该值执行拦截动作 |
| 拦截动作 | `spam` / `rejected` | 达到下限后的状态 |
| 最短填写时间 | 0–300 秒 | 低于该时长增加提交速度风险 |
| 表单有效期 | 1–10080 分钟 | 超时增加表单停留风险 |
| 链接上限 | 0–10 | 超出部分按条累积风险 |
| 重复检测窗口 | 0–1440 分钟 | 为 0 时关闭重复检测 |
| 重复内容允许次数 | 0–20 | 超过次数累积重复风险 |
| 来源频率窗口 | 1–1440 分钟 | 统计同 IP 哈希的历史留言 |
| 同来源留言上限 | 1–100 | 超过上限累积来源频率风险 |
| 违禁关键词 | 最多 1000 项，单项 ≤40 字符 | 命中后累积风险；支持 CSV/TXT 导入 |
| 昵称黑名单 | 最多 1000 项，单项 ≤40 字符 | 精确命中后累积风险；支持 CSV/TXT 导入 |

判定规则：

- 蜜罐字段非空是硬规则，直接 `spam`，不受阈值与启用状态影响。
- 风险分由规则权重累加并封顶 100；每条规则产生稳定的机器码、中文标签与权重。
- `score <= 自动发布上限` 为 `approved`；`score >= 自动拦截下限` 按策略拦截；其余为 `pending`。
- 自动关闭时仍计算风险分与原因，但结果固定为 `pending`，用于后续复核。
- 判定结果写入 `comment_moderation`，包含动作、分数、原因、策略修订与时间；原因只对管理端可见，不进入公开 DTO。
- 自动发布与拦截写入 `moderation_audit`；自动待审只写 `comment_moderation`，不写审计。
- 保存策略时，同一事务内写入修订并复核全部存量待审留言；只对仍为 `pending` 且未删除的记录做条件更新，避免覆盖人工处置。
- 自动审核不绕过限流、幂等、Origin、蜜罐、长度校验与父评论校验。
- 词表导入只在管理端：支持 UTF-8 `.csv`（取第一列，可带表头）与 `.txt`（换行或「、」分隔）；单文件 ≤1MB，单表 ≤1000 项，单项 ≤40 字符；导入前展示去重与非法项计数，支持追加或替换，最终仍由服务端 Zod 校验。

## 7. 反垃圾与限流

### 7.1 分层

1. **Nginx**：IP 级粗粒度限流、请求体大小限制、连接限制。
2. **应用层**：IP 哈希滑动窗口；IP 5/min、20/hour。
3. **表单层**：蜜罐字段、最短填写时间、重复内容检测、链接数量限制。
4. **人机验证**：可插拔 ALTCHA 或极验；默认关闭，按攻击情况启用。
5. **审核层**：新评论先经自动审核策略；低风险即时发布，边界风险进入待审，高风险按策略拦截；管理员保留人工兜底能力。

### 7.2 行为

- 触发限流：返回 `429 K1-CMT-007`，不泄露具体阈值。
- 明显垃圾：存储为 `spam`，返回 `202` 通用成功，避免教机器人绕过。
- 自动审核命中拦截阈值：写为 `rejected` 或 `spam`，返回 `202` 通用成功，不泄露具体规则；人工接口的明确违规仍返回 `422 K1-CMT-005`。
- 重复幂等键：返回第一次结果，不重复写库、不重复发通知。
- 同一 IP 短时间多条：累积来源频率风险；未达拦截阈值时进入待审，不直接公开。
- 管理员可在台账查看风险分、原因、策略修订与人工处置记录；达到拦截阈值的记录不得自动公开。

### 7.3 禁止

- 不做无上限的自动公开：自动发布必须受策略阈值、硬规则、审计与人工回滚约束；
- 不在客户端做唯一可信的来源校验；
- 不把 IP 明文写日志或响应；
- 不用前端隐藏字段作为唯一反垃圾手段；
- 不因反垃圾失败而丢弃合法评论且不记录；
- 不在自动判定中调用外部模型或网络服务，不把用户内容发送到第三方。

## 8. 评论 API 与 DTO

接口、状态码、错误码严格按 `02`：

- `GET /api/v1/posts/{slug}/comments?cursor=&limit=`
- `POST /api/v1/posts/{slug}/comments`
- `GET /api/v1/admin/comments?status=&page=&pageSize=`
- `PATCH /api/v1/admin/comments/{id}`
- `DELETE /api/v1/admin/comments/{id}`
- `GET /api/v1/admin/moderation/policy`
- `PUT /api/v1/admin/moderation/policy`

公开提交响应只暴露 `id` 与 `approved` / `pending`，不公开 `rejected` / `spam` 分类。

公开 DTO 只允许：

```text
id, parentId, authorName, content, createdAt, status(approved), repliesCount
```

禁止公开：IP、UA、幂等键、审核备注、管理员 ID、内部风险标记、自动审核分数与原因。

管理端 DTO 可包含审核所需字段与 `automation`（动作、分数、原因、策略修订、判定时间），但不返回 IP、UA 或任何身份信息。

## 9. 管理端与审核

- 认证：Better Auth；会话 Cookie 安全属性；登录限流。
- 授权：管理员角色；最小权限；不得用公开接口绕过。
- CSRF：所有写请求校验；失败返回 `403 K1-AUTH-003`。
- 自动化控制台：显示运行状态、策略修订、待审数、24 小时自动发布/拦截数；参数表单覆盖阈值、节奏、来源频率与词表。
- 策略保存：CSRF 校验；Zod 校验；追加策略修订；同一事务内复核存量待审；返回复核计数。
- 留言台账：按状态、时间分页；显示正文、昵称、自动判定、风险分、原因、策略修订与人工处置标记。
- 操作：通过、拒绝、标记垃圾、软删除、恢复（如允许）；每次操作写审计。
- 批量操作：必须二次确认；批量删除不可逆时先备份；审计记录批次。
- 审计字段：操作者、动作、前后状态、评论 ID、备注、时间；自动操作使用固定系统操作者标识。
- 管理端 UI 使用设计系统；不使用表格库默认主题；错误红字直陈。

## 10. 隐私与数据保护

### 10.1 身份信息

- 留言只收集昵称与正文；不收集邮箱、电话或任何账号信息。
- 昵称仅用于公开展示，不参与限流或去重。

### 10.2 IP 与 UA

- IP 只存哈希：`HMAC-SHA256("ip:" + IP, COMMENT_IP_PEPPER)`。
- User-Agent 只存截断摘要（≤120 字符），用于排障；不存完整 UA。
- 日志不记录原始 IP、Cookie、令牌。
- 代理层传递的真实 IP 只信任 Nginx 配置的头部；不得直接信任客户端头。

### 10.3 数据主体权利

- 提供删除请求渠道；删除评论时软删除并清理 UA/IP 哈希（或按保留策略）。
- 导出请求只导出该留言的公开字段与时间；不导出他人数据。
- 删除/导出操作必须审计；不得在日志中留下明文 IP。
- 隐私说明必须说明采集字段、用途、保留期限、联系渠道。

### 10.4 数据生命周期

| 数据 | 保留 |
| --- | --- |
| 已通过评论 | 长期，直到删除请求 |
| 待审 | 30 天 |
| 拒绝/垃圾 | 30 天 |
| 软删除 | 无回复的软删除评论 30 天后硬删除；有回复的父评论保留墓碑 |
| 自动判定记录 | 随评论保留；评论物理清理时级联删除 |
| 策略修订 | 长期保留，作为判定可追溯依据 |
| 审核审计 | 180 天 |
| 备份 | 30 天 |

## 11. 数据备份与恢复

- 每日 SQLite 在线备份；备份前/迁移前额外备份。
- 备份文件加密、限权、异机/对象存储；不与数据库同盘。
- 每次备份执行完整性检查；记录校验值、大小、时间。
- 每月恢复演练：恢复到临时目录、打开数据库、抽查评论与审计、核对迁移版本。
- 恢复流程：停止应用 → 备份当前库 → 恢复目标库 → 校验 → 启动 → 健康检查 → 冒烟。
- 恢复操作必须记录操作者、时间、来源备份、结果；不得在恢复过程中覆盖唯一可用备份。
- 迁移失败时优先恢复迁移前备份；不得在损坏库上继续写入。

## 12. 邮件通知

- 使用 SMTP + Nodemailer；凭据来自环境变量/密钥托管。
- 待审评论通知管理员；自动发布与自动拦截不发送通知；仅事务性邮件。
- 邮件模板使用纯文本/简洁 HTML；不嵌入跟踪像素；不泄露其他评论者信息。
- 邮件发送失败只记录日志，不回滚评论；不得阻塞用户提交。
- 邮件中的管理链接必须带签名令牌、有效期、一次性使用；不得直接暴露管理端路径。
- 日志不记录完整邮箱、SMTP 凭据、令牌。

## 13. 测试与验收

必须覆盖：

- frontmatter：缺字段、非法 slug、重复 slug、草稿、非法标签、图片无 alt。
- MDX：非法组件、脚本、远程 import、代码块语言、断链。
- 评论：空/超长/纯空白、非法父评论、层级超限、蜜罐、时间陷阱、限流、幂等、自动发布可见、边界风险待审、自动拦截不可见、人工通过/拒绝、软删除、审计写入。
- 自动审核：普通留言 0 分发布、蜜罐直接拦截、违禁词与快速提交待审、重复与来源频率组合拦截、关闭后全量待审、策略阈值互斥校验、词表去重、保存策略后存量复核。
- 管理端：未登录、会话过期、CSRF 缺失、越权、并发审核冲突、批量操作确认、策略保存校验。
- 数据：迁移空库/既有库、外键、备份恢复、保留策略。
- UI：评论表单空白、错误红字、待审状态、触屏可操作、键盘可操作、减少动效。
